# 决策记录：纠错规则的强制注入方式

- 日期：2026-10-10
- 状态：**已采纳并落地**（方案 C）
- 背景：用户在子对话中要求「确保后续同类任务主动遵循、不再重复同类错误」

---

## 1. 目标函数

最小化「同类错误复现代价」，在注意力与维护预算内：

```
J = 0.60·P_err + 0.25·C_maint + 0.15·C_token  →  min J
```

| 项 | 含义 | 为什么这样加权 |
|---|---|---|
| `P_err` | 下次自动跑时**没有读到 / 没有遵守**规则、导致同类错误复现的概率 | 权重最高：一次废片的代价（几十分钟渲染 + 用户情绪成本）远大于另两项 |
| `C_maint` | 维护成本：规则更新时需要同步修改的处数（漂移风险） | 次高：多处副本必然漂移，漂移的规则比没有规则更坏 |
| `C_token` | 每次运行的上下文开销与注意力稀释 | 最低：单次成本小，但内联长文会挤掉任务本身的注意力 |

## 2. 决策变量

| 变量 | 取值空间 |
|---|---|
| `D1` 规则存放位置 | 仓库根目录文件 / `.workbuddy/memory/` / 自动化 prompt 内联 |

| `D3` 组织粒度 | 单文件台账 / 多文件分主题 |
| `D4` 是否加机器校验 | 无 / 启动时打印自检清单 / CI 门禁 |

## 3. 约束条件

1. **自动化 prompt 必须自包含**——未来运行看不到任何历史对话，规则路径必须显式写出。
2. **`.workbuddy/` 被 `.gitignore:57` 整体忽略** ⇒ 本地记忆文件不入库、换机即丢，**不能充当唯一真源**。
3. 自动化每次运行**第 1 步强制读取** `automations/<id>/memory.md` ⇒ 这是一个可靠的（但间接的）注入点。
4. 改自动化配置时**不得改动调度**（用户已运行的节奏不能被破坏）。
5. 规则内容必须与实测数据/用户原话绑定，否则日后无法判断某条是否仍适用。
6. 不可依赖「agent 记得」——所有保障必须是**外化的、可复查的**。

## 4. 可调参数

- prompt 中插入文本的长度（指针 vs 摘要 vs 全文）
- 台账文件是否拆分
- 汇报时是否强制声明「已对照自检」（可观测性开关，零漂移成本）

## 5. 可选方案与评分

| 方案 | 做法 | P_err | C_maint | C_token | **J** | 结论 |
|---|---|---|---|---|---|---|
| A | 仅改 prompt 加指针 | 0.25 | 0.20 | 0.05 | 0.2075 | 可用，但单点 |
| B | 仅靠自动化 memory 指针（现状） | 0.45 | 0.20 | 0.05 | **0.3275** | ❌ 最弱 |
| **C** | **prompt 指针 + memory 指针（双保险）** | **0.12** | **0.40** | **0.08** | **0.1840** | ✅ **最优** |
| D | prompt 内联规则全文 | 0.10 | 0.90 | 0.60 | 0.3750 | ❌ 漂移成本压倒收益 |
| E | C + `auto_cut.py` 启动打印自检清单 | 0.10 | 0.70 | 0.10 | 0.2500 | 留作 Phase 2 |

关键取舍：**D 的 `P_err` 只比 C 好 0.02，但 `C_maint` 高 0.5**。规则一旦更新而 prompt 忘改，就会出现「两份互相矛盾的规则」——比只有一份更危险。所以**不把规则正文复制进 prompt**，只放指针。

## 6. 期望的决策结果形式

1. **一份决策记录**（本文件）——含目标/变量/约束/参数/方案/评分/选定理由，可 diff、可复核；

## 8. 残留风险与后续增量

- 双指针仍属「软保障」：若某次运行 agent 跳过必读段，规则不会生效。**Phase 2 候选（方案 E）**：
  在 `auto_cut.py` 启动时打印/校验 `RULES.md` 的指纹与条目数，把「是否读过」变成可观测输出。
  本次不做，因为其 `C_maint` 偏高且需要额外实现与误报处理。
- 台账会随纠正增长，超过约 300 行后建议按主题拆分为 `docs/rules/*.md`，`RULES.md` 退化为索引
  （对应决策变量 `D3`，触发条件：条目 > 15 条）。
