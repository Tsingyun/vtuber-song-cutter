# 透明底立绘进视频：方法、演出手法与残缺素材处置

> 2026-10-30 · 素材实测 145 张（本地 `Pictures/管人立绘/岁己立绘`，不入库）
> 参考来源：GitHub 一手项目 + 日站制作资料（详见 §8）
> 本文只写**做法**，不产出成片。

---

## 0. 结论先行

1. **透明底的最大价值不是"抠图方便"，是"轮廓可以随意介入版面"**。
   方框/圆框是被迫的遮丑，透明底真正的语法是：人物压过歌词、从画框外长进来、被笔刷擦掉一半、只剩一个剪影。
2. **素材要分档用**，不是一视同仁。实测里能"整幅大用"的只有 20 张，其余 125 张各有各的限制（§1）。
3. **56.8% 的素材左右被切**，其中 **58 张是两侧都切**——这 58 张用"出血构图"救不了（推出去一边，另一边缺口还在），必须走剪影 / 特写 / 遮挡 / 幻影 / 补全 五选一（§5）。
4. **分辨率是硬约束**：短边中位 1080，而 4K 里人物高度 90% 画高 = 1944px，意味着 1.8× 上采样。大面积全屏只能挑 A 档（§1.3）。
5. **性价比最高的三件套是「出血压字 + 局部特写 + 剪影」**——不需要任何 AI、不需要分层、不需要绑骨骼，靠排版就能覆盖大约 80% 的镜头需求。AI 补全只值得对"要反复大用的 5~10 张"做一次。

### 1.3 分辨率预算

| 指标 | 数值 |
|---|---|
| 短边中位 / 最小 | **1080 px / 400 px** |
| 短边 <1000（低分件） | **49 张** |
| 原生 RGBA 纹理中位 | 9.6 MiB |
| 最大单张纹理 | 92 MiB（5184×13096） |
| 全量常驻显存 | **1.8 GiB**（不可全量缓存） |
| >64 MiB 的素材 | 5 张 |

**换算**：4K 画幅 3840×2160，人物占 90% 画高 → 需要 1944px 高的像素。
短边 1080 的图放满屏 = 1.8× 上采样（平涂二次元尚可，线条会软一档）；短边 400 的图 = 4.9×，只能当 300px 小卡片或虚化幻影。

### 1.4 分档（决定"能怎么用"）

| 档 | 判据 | 数量 | 用法 |
|---|---|---|---|
| **A 可整幅大用** | 不触边 且 短边 ≥1400 | **20** | 全屏站立、2.5D 视差、主视觉 |
| **B 完整但分辨率一般** | 不触边 且 短边 1000~1400 | **33** | 半屏（≤70% 画高）、分屏一格 |
| **C 残缺但可出血** | 触边 且 短边 ≥1000 | **43** | 出血构图、贴边站立、被字压 |
| **D 低分 / 极端裁切** | 短边 <1000 或 头区>0.92 | **49** | 特写 insert、小卡片、幻影、背景虚格 |

## 2. 五条技术路线（先选路线，再谈手法）

| # | 路线 | 核心做法 | 一次性成本 | 每帧成本 | 效果上限 | 适合 |
|---|---|---|---|---|---|---|
| 1 | **静态贴图 + 2D 变换** | PNG 直接画，加呼吸/漂移/推拉/旋转 | 0 | 极低（drawImage） | 中（"会呼吸的立牌"） | 90% 的镜头 |
| 2 | **分层视差** | 拆 2~4 层（后发 / 身体 / 前发 / 前景饰物），各层位移量不同 | 手拆 20~40 分钟/张；[See-through](https://github.com/shitagaki-lab/see-through) 自动拆 23 层 | 低（N 次 drawImage） | 高（转头、发梢飘、衣服滞后） | 主角镜头、需要"活"的地方 |
| 3 | **深度图 2.5D** | 估深度 → 按深度做位移/景深，相机推进时近处快、远处慢 | 一张图跑一次深度（Depth Anything / Marigold） | 中（需 WebGL 或位移网格） | 很高（真体积感） | **背景/场景**，不适合人物（脸会拉丝） |
| 4 | **生成式补全** | outpainting 补被裁掉的头发；inpainting 补被遮住的部位 | 每张 1~3 分钟 + 人工挑 | 0 | 解缺陷（把残缺件变成完整件） | 5~10 张"要反复大用"的 |
| 5 | **骨骼绑定** | Live2D / [Inochi2D](https://inochi2d.com) / AE  puppet 打点 | 极重（数小时/张），且要分层 | 低 | 最高（可演） | **本项目不做**，成本与收益不成比例 |

**推荐组合**：**1 为默认，2 用在副歌主镜，4 只对 A 档里最重要的几张做，3 只给背景，5 放弃。**
理由：一首歌 49 个镜头，做绑定的时间足够重排十首歌的版面；而"分层视差"能把 80% 的"活"做出来，成本是 20 分钟/张。

## 3. 预处理 SOP（7 步，一次性做完）

### 3.1 去边（白边 / 黑边）
透明 PNG 的白边不是"画上去的",是 alpha 边缘的 RGB 被原来背景污染（straight alpha 的典型残留）。三种处理，按严重度选：

| 情况 | 处理 | 工具 |
|---|---|---|
| 边缘 1~2px 发白/发灰 | 收缩 alpha 1px（erode）+ 轻微 despill | PIL/numpy 三行；或 [PVL Edge Extend](https://comfy.icu/node/PVL_EdgeExtend) 的 `alpha_erode_after_levels` |
| 边缘一整圈灰蒙蒙 | Nuke 式 edge extend：把 alpha 往外"长"1~3px，用边缘色填 | 同上（ComfyUI 节点），或手写 numpy 膨胀+近邻填充 |
| 原图是白底 JPG 硬抠的 | 重抠，开 alpha matting | `rembg i in.png out.png -a`；更好的是 [BiRefNet](https://github.com/ZhengPeng7/BiRefNet) |
| 二次元专用抠图 | 用 anime 分割模型 | IOPaint 的 `--enable-remove-bg` / Anime Segmentation 插件 |

> **不要**在合成阶段用"描边"盖白边——在 4K 上会读成一圈贴纸轮廓（这与本项目文字层踩过的坑同源）。

### 3.2 归一（bbox + baseline）
把每张图按 alpha 包围盒裁掉空边，记录三个数：`bbox`、`baseline`（下缘在画面里的位置）、`head_y`（头顶高度）。
后两个决定"人物站在哪"——所有立绘必须共用同一条地平线，否则一排人会飘。

### 3.3 发丝（半透明像素）
发梢的 alpha 常常是 0.2~0.8 的连续值。两条纪律：
- **不要二值化**。二值化后发丝变成锯齿硬块，叠在浅色纸上尤其明显。
- **缩图用面积平均**（PIL `Image.LANCZOS` / Canvas `imageSmoothingQuality='high'`），不要最近邻——最近邻会把半透明像素丢掉，发梢直接消失。

### 3.4 色温统一
立绘多是冷调高饱和（直播/同人图通用色），纸面是暖褐。硬边并置的第一眼读感是"贴纸"。
沿用引擎已有的 `tintPlate` 参数：`multiply(纸色, α·0.30k)` + `screen(暖光, α·0.13k)`，`k=1` 时约 −30% 饱和 + 暖高光。
**注意**：叠色必须发生在**羽化之前**（否则羽化边缘会出现一条直的角色温矩形边）。

### 3.5 分辨率预算
目标像素高 `H_t`（= 画高 × 占比），要求 `源短边 ≥ 1.2 × H_t`。
不满足时三条路：**缩小构图**（改特写/卡片）、**预上采样一次并缓存**（RealESRGAN / waifu2x，只做一次）、**接受软化**（平涂画风可以忍，线稿风不行）。

### 3.6 纹理预算
145 张全量 1.8 GiB，必须按需加载：
- 加载时按 `min(1, H_t·1.25 / 源高)` 降采样到目标尺寸再上传，单张 ≤32 MiB；
- LRU 缓存 12~16 张（覆盖前后 2 个镜头）；
- 5 张超过 64 MiB 的（含 5184×13096 那张）单独走"预降采样"路径，加载即缩。

### 3.7 清单
生成 `assets/art/manifest.json`，字段至少：

```json
{ "id": "1096585956236984324_00",
  "file": "...", "w": 1200, "h": 1800,
  "form": "全身竖构", "ar": 1.50,
  "bbox": [12, 4, 1188, 1796], "baseline": 0.997,
  "head_span": 0.61,
  "clipped": {"l": false, "r": false, "t": false, "b": true},
  "grade": "A", "tags": ["白毛", "红贝雷", "wings"] }
```

`grade` + `clipped` 这两个字段是后面所有门禁的判据来源。

## 4. 日本二次元 PV 的 14 种入画手法

按"是否需要透明底"和"是否救得了残缺件"排序。

| # | 手法 | 画面读感 | 救残缺? | 成本 | 关键参数 |
|---|---|---|---|---|---|
| 1 | **出血压字**（人物从下缘长进画面，字被压在胸/肩前） | "她在这个版面上"，最像手书 PV | ✅ 底切天然成立 | 低 | 人物下缘 = 画高 +2~6%；字层在人物后 |
| 2 | **人物压字**（人物层在最上，歌词从其身前穿过） | 层次感，最高级的一招 | ✅ 侧切可藏 | 低 | 人物层 `layer:"front"`；字加深色描边保可读 |
| 3 | **局部特写 insert**（只取眼、手、发梢、领结） | 节奏重音，剪辑点 | ✅ 切边变画框 | 低 | 取景 ≤25% 画幅，配 0.6~1.2s |
| 4 | **剪影 / 逆光**（纯黑或单色剪影 + 边缘光） | 情绪爆发、副歌前 | ✅✅ 缺口完全消失 | 低 | 二值化 + 轮廓 2~4px 亮边 |
| 5 | **半调 / 双色调**（网点、套色错位、单色） | 印刷感、复古 | ✅ 细节缺失读不出来 | 低 | 网点 6~10px；错位 2~3px |
| 6 | **卡片 / 拍立得 / 剪贴簿**（人物裁进相纸，叠角标、胶带） | 回忆、日记 | ✅ 方框本来就是裁切 | 低 | 相纸白边 2~3% 画宽，微旋转 ±2° |
| 7 | **分屏 / 漫画分格**（2~4 格各放一人/一表情） | 信息密度、对唱感 | ✅ 单格裁切合理 | 中 | 格间距 1.5% 画宽，斜切 6~10° |
| 8 | **幻影 / 残影**（低透明 + 模糊 + 多份偏移） | 记忆、回声、速度 | ✅ 虚化后缺口不可见 | 低 | 3~5 份，偏移 8~20px，α 0.08~0.18 |
| 9 | **笔刷 / 撕纸擦除**（人物沿手绘笔触被"长出来"或"吃掉") | 手书感最强 | ✅ 缺口被笔触盖住 | 中 | 笔触 alpha 遮罩，0.5~0.9s |
| 10 | **滑入 / 出画**（从左右边缘横移进画面） | 节奏、段落切换 | ⚠️ 只适合完整件 | 低 | 位移 30~50% 画宽，缓动 out-cubic |
| 11 | **2.5D 视差推进**（分层 + 相机 dolly） | 电影感、呼吸感 | ⚠️ 位移越大越露 | 中 | 层间位移差 1.5~3%，总位移 ≤4% 画宽 |
| 12 | **故障切片**（横向错位 + RGB 分离） | 冲击、失真 | ✅ 错位掩盖断口 | 低 | 切片 6~14 条，单条错位 ≤40px |
| 13 | **前景遮挡**（花瓣、光斑、纸屑、雨丝飘过人物前） | 空间纵深 | ✅ 缺口正好被挡 | 低 | 前景层 α 0.5~0.9，视差 1.4× |
| 14 | **呼吸微动 + 眨眼**（±0.9% 缩放 + 7px 漂移 + 3 帧闭眼） | "她在动" | — | 低 | 周期 8~12s，相位错开 |

### 4.1 详解：最值得先做的三种

**① 出血压字（Bleed + Overlap）**
人物只画到胸口，下缘压在画面外 2~6% 处，膝盖以下全不要。歌词从人物身前穿过，人物层 `layer:"front"`。
为什么这是手书 PV 的第一语法：它同时解决三件事——隐藏底切、建立"她在版面里"的空间关系、给字让出上半部的干净纸面。
参数：人物占画高 **62~78%**，水平锚点 `x = 0.5±0.18`，与字的重叠面积控制在 10~25%（全压会糊，不压就没层次）。

**② 剪影 / 逆光（Silhouette）**
把 RGB 压成单色（纸色偏深一档），只留轮廓，再沿 alpha 边缘画 2~4px 亮边（`screen` 暖光）。
这是**残缺件的万能解**：一旦只剩轮廓，"头发被切掉一块"变成"逆光里的一个形状"，观众不会去数发丝。
判据：剪影必须**小于**原图尺寸的 1.15×，否则缺口会被放大成明显缺口。

**③ 局部特写（Insert）**
只取 `bbox` 的 15~30% 区域（眼、嘴、手、耳饰），配 0.6~1.2s，落在鼓点或换气处。
它把"裁切边"直接变成"画面边"——因为观众默认特写就是裁过的。
一首歌 8~12 个 insert 就够，且它们是**唯一能安全使用 D 档低分素材**的手法。

## 5. 残缺素材：判定与 9 条规避

### 5.1 判定阈值（写进 manifest，机器可判）

| 缺陷 | 判据 | 本批数量 | 严重度 |
|---|---|---|---|
| 单侧侧切 | 一侧 `touch > 0.05`，另一侧 <0.02 | 13 | 轻（出血可救） |
| **双侧侧切** | 两侧 `touch > 0.05` | **58** | 重（出血救不了） |
| 顶切 | `touch_t > 0.2` | 5 | 最重（脸/头顶缺） |
| 底切 | `touch_b > 0.9` | 44 | 不算缺陷 |
| 低分 | 短边 <1000 | 49 | 中（限尺寸） |
| 超近景 | `head_span > 0.92` | 49 | 中（只能特写） |
| 无 alpha | `alpha.min()==255` | 1（+24 JPG） | 不可直接用 |

### 5.2 九条规避，按优先级

| # | 手法 | 适用缺陷 | 做法 | 代价 | 优先级 |
|---|---|---|---|---|---|
| 1 | **出血构图** | 单侧切、底切 | 把被切的那一侧**推出画外**，让裁切边永远不进入画面；只露"好的那一半" | 0 | ★★★★★ |
| 2 | **局部特写** | 全部 | 只取脸/眼，裁切边即画框 | 0 | ★★★★★ |
| 3 | **遮挡设计** | 双侧切、顶切 | 让笔刷、花瓣、色块、标题字**正好压在缺口**上（把缺陷变成构图点） | 0 | ★★★★★ |
| 4 | **剪影 / 半调 / 双色调** | 双侧切、顶切 | 抹掉细节判据，只留形状 | 低 | ★★★★☆ |
| 5 | **幻影 / 残影** | 双侧切、低分 | 虚化 + 低透明 + 多份偏移，缺口糊掉 | 低 | ★★★★☆ |
| 6 | **边缘光包裹** | 双侧切 | 沿 alpha 边缘画亮边，让"断口"读成"光溢出" | 低 | ★★★☆☆ |
| 7 | **运动约束** | 双侧切 | 禁止横向 pan/dolly；只做纵向推拉 + 缩放；总位移 ≤ 缺口余量（缺口 <5% 画宽时位移 ≤3%） | 0 | ★★★★☆ |
| 8 | **镜像补全** | 单侧切、对称发型 | 水平翻转拼接被切的一段 | 低 | ★★☆☆☆（仅缺口 ≤3% 宽、且发缝左右对称时） |
| 9 | **生成式补全** | 双侧切、顶切 | outpainting 补头发、inpainting 补被遮部位 | 1~3 分钟/张 + 人工挑 | ★★★☆☆（只做"要反复大用"的 5~10 张） |

### 5.3 关键判断：双侧切的 58 张怎么办

双侧都缺 → **出血只能救一边**，另一边必然露缺口。三选一：

- **A. 改语法**：剪影（手法 4）/ 半调（5）/ 特写（3）——零成本，推荐给大部分；
- **B. 改遮挡**：让版面元素压上去（3）——需要导演层配合，等于"设计一个缺口"；
- **C. 改素材**：补全（9）——只对 A 档里反复出现的那几张做。

**反例（不要做）**：把两侧缺口用"模糊+拉伸"糊过去。4K 下会读成"人物被压扁"，比缺口更糟。

### 5.4 顶切（5 张）的处理
头顶被切是唯一"不能靠构图绕开"的缺陷（观众的注意力在眼睛以上）。
三条：① 只取到肩部，头顶**在画外**（让"看不到头顶"变成刻意的近景）；② 用标题字/纸条压在头顶位置；③ 补全（inpainting 补额头以上）。

### 5.5 低分（49 张）的尺寸上限
`可用像素高 = 短边 × 1.25`（容忍 1.25× 上采样）。短边 400 → 只有 500px 高，只能当：
- 小卡片（≤12% 画高）
- 幻影 / 背景格
- 网点化后的小图标

## 6. 接进现有引擎：需要新开一层，不能复用 `drawFigure`

### 6.1 为什么不能复用
现有 `drawFigure`（`pv_engine.js:451`）有三个写死的假设，全都不适用于静态立绘：

| 现有假设 | 代码位置 | 对静态立绘的后果 |
|---|---|---|
| 输入是**序列帧**（`ST.seq[name]` + `getFrame`） | `drawFigure` 开头 | 立绘根本没有 seq，直接 return，**静默不显示** |
| 用 **cover 裁切**填满矩形框（`drawCoverF`） | `figBitmap` | 会把人裁成"只有胸口一块"，头被切掉 |
| 离屏压到 **760px** 再放大 | `figBitmap` 第 363 行 | 全屏立绘从 760px 拉到 4K，糊成一片 |

结论：**新增 `pv_art.js` + `drawArt()`**，与 `drawFigure` 并列，互不干扰；`drawFigure` 继续服务直播切片。

### 6.2 镜头 spec 草案

```js
shot.art = {
  id: "1096585956236984324_00",   // manifest 键
  mode: "bleed",                  // bleed|bust|insert|sil|halftone|card|ghost|split|swipe|glitch
  side: "r",                      // 锚定侧
  h: 0.72,                        // 目标高 / 画高
  x: 0.62, y: 1.02,               // 锚点（>1 即出血）
  zoom: 1.0, fx: 0.5, fy: 0.30,   // 取景中心（insert 模式用）
  rot: -2,                        // 度
  alpha: 1,                       // 整体不透明
  parallax: 0.0,                  // 分层视差强度（0 = 单层）
  motion: 1,                      // 呼吸/漂移倍率
  ph: 0.3,                        // 相位，避免多镜同步呼吸
  paper: 0.8,                     // 纸色温混合强度
  layer: "front",                 // front = 压字
  tIn:  ["brush", 0.55],          // 入场：笔刷长出来
  tOut: ["fade", 0.35]
};
```

### 6.3 门禁（渲染前静态检查，违反即 exit）

1. `id` 在 manifest 中存在，且 `alpha` 有效（否则报错，不静默跳过）；
2. `h × 画高 ≤ 源短边 × 1.25`（超了警告并自动降 `h`）；
3. `mode ∈ {swipe, dolly}` 且 `clipped.l || clipped.r` → **拒绝**（残缺件禁止横移）；
4. `layer:"front"` 时，人物 bbox 与歌词版心重叠 >45% → 警告（字会不可读）；
5. 单镜头纹理总量 ≤ 96 MiB；全场常驻 ≤ 512 MiB。

### 6.4 性能估算
Canvas 2D 的 `drawImage`（GPU 后端）在 4K 下每次约 4~9ms（含缩放）。一个人物 = 1~3 次绘制（主体 + 前景层 + 边缘光）⇒ **8~25ms/帧**。
当前渲染约 77ms/帧（13fps），加入人物层后预计 85~100ms/帧（10~12fps）——**可接受**，不必上 WebGL。
前提是 §3.6 的降采样缓存：直接贴 92 MiB 的原图会掉到 3fps。

## 7. 人物 70%：时间表模板

> 目标：**出镜时长 ≥ 总时长 × 70%**（231.7s 的片子 ⇒ ≥162s），且**平均像素覆盖 ≥28% 画幅**（只在角落放个小头像不算"人物在"）。

| 段落 | 时长 | 人物出镜 | 主导手法 |
|---|---|---|---|
| 前奏 | 0:00–0:12 | 30% | 纸面 + 标题（先不出现，建立材质） |
| 主歌 1 | 0:12–0:55 | 75% | 出血压字 + 局部特写 |
| 副歌 1 | 0:55–1:25 | 92% | 剪影 + 分屏 + 前景花瓣 |
| 间奏 | 1:25–1:45 | 65% | 幻影 / 半调 / 卡片 |
| 主歌 2 | 1:45–2:20 | 80% | 2.5D 视差 + 双人分屏 |
| 副歌 2 | 2:20–3:05 | 95% | 全屏站立 + 故障切片 |
| 尾奏 | 3:05–3:32 | 55% | 出血 + 渐隐 |
| **加权** | 231.7s | **≈74%** | |

配套纪律（与直播层共用一套判据）：
- 人物镜与纯字镜**必须交替**，连续 3 镜都有人的话，第 4 镜要放空；
- 相邻两镜人物**锚定侧要换边**（l r l r），否则读成"人物卡住了"；
- 人物与字的**最小间隔** ≥4s（否则节奏糊）；
- 每个副歌至少 1 个 0.6~1.2s 的 insert 打点。
