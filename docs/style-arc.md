# 风格弧线（style arc）—— 让纸跟着歌词走

> 对应实现：`tools/pv_arc.py`（算曲线）、`renderer/player/pv/pv_arc.js`（运行时）、
> `tools/pv_direct.py --arc`（接线）、`tools/pv_arc_plot.py`（检查图）
> 首版：2026-11-01　分支：`feature/ref-style-pv`

---

## 1. 一句话

原来的换纸只认**曲式**（段落 A/B/C），现在的换纸还认**内容**（这一句在说什么），
并且把「换」这件事从硬切改成了三件事叠出来的平滑过渡。

---

## 2. 问题在哪

改造前的机制是：

```
段落 B5 → (pack=violet, scheme=0)  ← 一个段一套纸，段内每 24s 轮转一次
```

三个具体毛病：

1. **段内不换**。`SWITCH_EVERY = 24.0` 秒，而一段副歌常只有十几到三十几秒 ——
   `(sec.t1 - sec.t0) > 34` 这个前置条件在 35 秒的副歌里一次都不成立。
   实拍：改造前四句用的全是 `violet/1`（月白），四句一模一样。
2. **只认段落，不认句子**。「爱着你 像心跳难触摸」与「画不出你的骨骼」在情绪上
   是两件事，纸上却没有区别。
3. **换就是硬切**。段落边界直接换色，没有任何过渡时长。

---

## 3. 做法：五维连续坐标

不从预设里挑一套，而是把风格拆成五个**连续**维度：

| 维度 | 0 ↔ 1 | 用途 |
|---|---|---|
| `lum` | 夜 ↔ 纸 | 底色明暗，决定用哪一套 scheme |
| `warm` | 冷 ↔ 暖 | 色温；与彩度一起决定「哪一种夜」 |
| `dense` | 疏 ↔ 密 | 字距（`track`）与版心密度 |
| `motion` | 静 ↔ 动 | 转场族与转场时长 |
| `grain` | 净 ↔ 纸 | 颗粒强度 |

两个来源合成每一句的目标坐标：

```
目标 = 基准(0.34, 0.44, 0.52, 0.48, 0.50)
     + 意境偏移（词典，最多 ±0.30）
     + 曲风偏移（能量包络 → motion/dense/lum，BPM → motion）
```

- **意境**：`LEX` 五个词族（tender / ache / cold / vow / vast）。中文没有词边界，
  用子串命中，并按词长加权（2 字 = 1.0，4 字 = 2.0）——「爱」是万能字，
  「执着」是具体词，等权会把整首歌推成同一个方向。
- **曲风**：从 `analysis.json` 的 48 频段能量解出**局部**能量（不是 BPM —— BPM 是
  整首一个数，副歌和主歌一样快）。阈值 0.10~0.45 取自本曲实测分位。

### 一个必须说清的实测结论

单看《画心》副歌这 35 秒，四句的能量是 **0.414 / 0.409 / 0.408 / 0.366** —— 几乎是平的。
也就是说**在这一段里曲风项基本不起作用**，风格变化完全由歌词意境承担。

这不是缺陷。曲风项的价值在主歌↔副歌之间（整首渲染时 p50 从 0.26 到 0.40 是一个
实打实的台阶）。把它当成「每一句都会提供信息」，写出来的曲线必然会抖。

---

## 4. 平滑：三个机制，不是一种

用户的要求是「切换自然平滑、避免突兀」。这里最容易走错的一步是
**把两套配色线性糊成中间色** —— 得到的是灰，而且字与底的分离度同时下降。

实际采用了三层，各管一段：

### 4.1 句边界过渡（时间层）

关键帧只落在**句边界**：

```
(t0 - 0.6, 上一句的值) → (t0, 这一句的值)   smoothstep
```

- 句中恒定 —— 不会「字读到一半换了个色」；
- 落差全部发生在句边界前 0.6s 的缓动窗里，与转场时长（0.4~0.55s）同量级；
- 两端导数为 0（smoothstep），不会出现「色温突然开始变」的折角。

### 4.2 转场族与时长（空间层）

- `motion` 调转场时长：静 0.55s、动 0.30s；
- **跨深/浅换纸**（两套纸的底色亮度差 > 0.30）时强制 `grad`（软坡渐变擦除）
  并把时长拉到 ≥0.55s。

为什么必须是 `grad`：一开始用的是 `dissolve`（透明叠化），实测**不可用** ——
两镜都满字、大字位置不同时，叠化会把两层笔画压成一片黑糊
（t=20.5 的实拍帧：「是我一首」与「你的执着」重叠成一团）。
dissolve 只在两镜内容相近时成立，而「换纸」恰恰是内容最不相同的时刻。
`grad` 是空间上分开的：新画面从一侧推进，任何一帧都只有一个清晰的字层。

### 4.3 逐帧色温层（连续层）

`pv_arc.js` 的 `drawArcTone(t)` 每帧按曲线叠一层极薄的暖冷 / 明暗：

- 暖 `rgba(255,168,96)` / 冷 `rgba(104,146,255)`，上限 **0.075**；
- 明暗：压暗上限 0.070、提亮上限 0.045（提亮更容易洗掉暗部细节）；
- 全部 `source-over` + 纯色 + 常量 alpha —— 确定性由「纯色 + 常量」直接保证，
  也避免 `soft-light` / `overlay` 在不同 GPU 上实现不一致。

这一层的定位是**胶水**：它让「镜头之内」也一直在缓慢变化，而不是只在换镜时跳一下。
超过 0.10 就会开始吃掉字与底的分离度（深底上冷白字边缘出现一圈橙边）。

---

## 5. 换纸时另外两个必须做的动作

这两条是实测撞出来的，不写下来下次一定重犯。

### 5.1 上一镜的退场要走到底（`xKeep = 0.96`）

引擎默认 `X_KEEP = 0.55`：有下一镜的镜头，退场只走到 55%，剩下 45% 的墨量
留给转场去擦（这样切点瞬间「屏幕上的样子」与「快照 A」是同一张画，不会闪）。

但换纸时这条会坏事：快照 A 里压着 45% 的**上一句的字**，转场擦的就是它 ——
软坡里两层笔画打架。所以换纸镜头的**上一镜**把 `xKeep` 推到 0.96，
让快照 A 是一张近乎空白的纸。

退场走完本身也是对的叙事：上一句讲完了 → 字退干净 → 纸翻过去 → 新句长出来。

### 5.2 新镜的入场要推后（`lead ≥ 0.26`）

只推退场、不推入场的话，新句的字在转场还没走完时就已经出全了。
推后 0.26s（约 8 帧），软坡推进到一半时新字才开始长，重叠窗口就没了。

只对**换纸镜头**生效。普通换句推后 0.26s 会变成「字幕迟半拍」。

## 6. 本片的实际弧线

| 句 | 时间 | 意境命中 | lum / warm | 落地纸 |
|---|---|---|---|---|
| 爱着你 像心跳难触摸 | 0.00–6.50 | tender×2.0 | 0.66 / 0.74 | `#1` 月白 `#EDECF2` |
| 画着你 画不出你的骨骼 | 6.50–13.43 | ache×1.0 / vow×1.0 | 0.16 / 0.46 | `#3` 紫晕 `#241C33` |
| 记着你的脸色 是我等你的执着 | 13.43–20.37 | vow×4.0 | 0.20 / 0.68 | `#2` 靛 `#0C1024` |
| 你是我一首唱不完的歌 | 20.37–34.80 | vast×2.0 | 0.66 / 0.48 | `#1` 月白 `#EDECF2` |

走向：**月白 → 紫晕 → 靛 → 月白**。亮度先沉后扬，色温由暖转冷再回来。
换纸 3 次，平均 11.6 秒一次；两次跨深/浅（0.83 与 0.84），都配 `grad` 长转场。

### 6.1 客观核验（成片帧，取画面上方左右两角 180×180 中位色）

| 段 | 角落中位色 | 感知亮度 | 相对上一段 |
|---|---|---|---|
| 爱着你（t=3.0） | (0.92, 0.90, 0.92) | 0.90 | — |
| 画不出骨骼（t=9.0） | (0.12, 0.09, 0.18) | 0.10 | **−0.80（9 倍）** |
| 记着你的脸色（t=16.0） | (0.06, 0.06, 0.12) | 0.06 | −0.04（1.6 倍） |
| 唱不完的歌（t=24.0） | (0.92, 0.92, 0.94) | 0.92 | **+0.86（15 倍）** |

这张表要如实读：**主感知点是两次月白↔深色的大跳**（9 倍 / 15 倍亮度差），
第 2→3 句的「紫晕 → 靛」只有 0.04 的亮度差（1.6 倍），是**微调**不是切换 ——
两者的差别主要在彩度（紫红 ↔ 蓝紫）。

`violet` 这个 pack 的四套深底亮度是 0.002~0.014，天生做不出更大的明暗阶梯。
要更强的段内反差就得换 pack（`huaxin` 有素纸/月/夜/朱/烬五档），
但那会把整支片从冷光改成宣纸 —— 属于换风格，不是这一轮的目标。

### 为什么选纸要两维

`violet` 这个 pack 的五套 scheme，除「月白」外底色亮度是
**0.002 / 0.003 / 0.006 / 0.014** —— 按亮度根本分不开，四套会被判成同一套
（第一版就是这样，四句只有两种纸）。

但它们在观感上是四张不同的纸，差别在**彩度**：近黑 0.50 / 灰紫 0.33 /
蓝紫 0.67 / 中紫 0.45。所以坐标是二维的：

```
dist = 0.72 × |lum - lum_e| / 0.90  +  0.28 × |sat - warm_e|
```

亮度是主判据（「夜」与「纸」是两种东西），彩度是次级（同一种夜里挑哪一张）。
彩度权重再高，浅底与深底就会被判成近邻，跨侧大跳变成小碎步。

## 7. 接线位置（代码级）

```
tools/pv_arc.py
  build(lines, analysis, w0, dur)   → 关键帧 + 逐句判据
  Arc.at(t)                         → 任意时刻的五维坐标（smoothstep）
  Arc.pick(pack, t, schemes)        → 这一句用哪套纸（二维距离 + 滞回 + 最小停留）

tools/pv_direct.py  --arc
  ├─ 换纸：sch ← pick(...)，取代原来的段内 24s 轮转
  ├─ 字距：typ["track"] = vsp_tracking × (0.55 + 0.90 × dense)
  │        有档案时是**乘法**（基调 × 变化），不覆盖档案的性格
  ├─ 转场：dur ← trans_params(motion)；跨侧时强制 grad 且 ≥0.55s
  ├─ 换纸镜头：上一镜 xKeep=0.96，本镜 enter.lead ≥ 0.26
  ├─ shot.arc：逐镜坐标写进编排稿（给 probe / 人工核对）
  └─ sb.arc：整条曲线写进编排稿（渲染端只认它，不再回头算）

renderer/player/pv/pv_arc.js
  ├─ PV.setArc(sb.arc)    没有 arc 字段 → ARC=null，全部调用短路
  ├─ PV.arcAt(t)          与 Python 完全同一条 smoothstep
  ├─ PV.drawArcTone(t)    逐帧暖冷 / 明暗层（crossFade 之后、letterbox 之前）
  ├─ PV.arcGrain(t, base) 颗粒强度调制
  └─ PV.STYLE_MIX(...)    调色板加权混合（本版 arc 不产出 mix，留作接口）

renderer/player/pv/pv_engine.js
  ├─ setup：PV.setArc(opt.storyboard.arc)
  ├─ shot._pal：支持 pal.mix
  ├─ sh._xcap：支持 per-shot xKeep 覆盖
  └─ renderAt：tone 层 + 颗粒调制
```

**向后兼容**：不带 `--arc` 时 `_ARC = None`，编排稿里不会出现 `arc` 字段，
`pv_direct` 的每一次输出与改造前逐字段相同；引擎侧 `setArc(null)` 之后
`arcAt / drawArcTone / arcGrain` 全部短路。既有成片重渲不会变。

## 8. 复现

```bash
# 1) 编排（--arc 开启弧线，--arc-dump 落一份可检查的曲线）
python tools/pv_direct.py \
  --timing cuts/2026-10-31/画心/_work/timing.json \
  --analysis cuts/2026-10-31/画心/_work/analysis.json \
  --out _tmp/jz/chorus2/sb_arc.json \
  --start 216.33 --dur 34.8 --title 画心 --artist 张靓颖 --vocal 岁己SUI \
  --live cuts/2026-10-31/画心/_work/live/live.json \
  --fig-spans _tmp/jz/chorus2/fig_spans.json \
  --style styles/bv1juxc6seko.vsp.json --style-pack violet \
  --jz _tmp/jz/chorus2/jz.json --jz-alpha 0.40 \
  --arc --arc-dump _tmp/jz/chorus2/arc.json

# 2) 检查图（曲线 + 换纸点 + 每句的纸）
python tools/pv_arc_plot.py --arc _tmp/jz/chorus2/arc.json \
  --sb _tmp/jz/chorus2/sb_arc.json --out _tmp/jz/chorus2/arc.png

# 3) 抽帧（比全片快两个数量级，先看画面对不对）
node tools/pv_stills.cjs --sb _tmp/jz/chorus2/sb_arc.json \
  --times 3,9,16,24,30 --out _tmp/jz/chorus2/stills --res 1

# 4) 成片
node renderer/render_song.cjs --job _tmp/jz/chorus2/job_arc.json
```

> Playwright 不在项目内，跑 `pv_stills.cjs` / `render_song.cjs` 前需要
> `NODE_PATH` 指向本机已装 playwright 的目录。

## 9. 本轮撞到的四个坑

| # | 现象 | 真因 | 修法 |
|---|---|---|---|
| 1 | 深底镜头的背景浮出一整墙重复歌词 | JIZURA 层是 `screen` 合成 + 白字：**浅底天然不可见，深底才显形**。这个隐式假设在第一次出现深底镜头时被打破 | 深底镜头 `a × 0.14`（0.40 → 0.056） |
| 2 | 换纸瞬间两层大字压成黑糊 | `dissolve` 是时间叠化，两镜内容不同时必然糊 | 跨侧换纸强制 `grad`（空间分离） |
| 3 | 同上，光换转场还不够 | 快照 A 里仍有 45% 的旧字（`X_KEEP=0.55`） | 换纸时上一镜 `xKeep=0.96` |
| 4 | 四句只有两种纸 | 只按 `lum` 选纸，而 violet 四套深底亮度几乎相同 | 坐标改二维（亮度 + 彩度） |

第 1 条尤其值得记：它是「前一轮交付物在**新的条件下**才暴露的缺陷」。
上一轮全片都是月白底，JIZURA 层安安静静当背景；这一轮一旦有了深底镜头，
它立刻变成「同屏两套歌词」。

## 10. 未做 / 已知限制

- **`violet` 的 `glow` 与 tone 层没有耦合**：光晕色目前不随弧线漂移，只在 scheme 切换时换。
- **调色板混合（`PV.STYLE_MIX`）已实现但未启用**：混合会抹平两套纸的差异，
  而「换纸」正是观众感知段落的东西。留作后续「同侧微过渡」的实验接口。
- **意境词典只有 5 个词族、约 60 个词**，只覆盖中文。日文/英文歌目前只能靠曲风项，
  曲线会明显变平。扩展词表不需要改代码（`LEX` 是纯数据）。
- **曲风项在单段副歌里几乎不起作用**（见 §3 实测），长片（整首）才会体现。
- **JIZURA 自带歌词层无法关闭**：它是文字引擎，关掉 layout 就没有产物。
  深底镜头只能压暗，不能改成「只留动效装饰」。
