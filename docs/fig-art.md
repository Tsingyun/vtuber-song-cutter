# 立绘人物层（`art`）：用素材库的透明 PNG 做「文字穿过人物」

> 2026-11-03 改向。本文记录**为什么改**、**怎么选图**、**怎么实现**，以及
> 「怎样才算做对了」的验收口径。代码分布在三处，读之前先看这张地图：

| 位置 | 职责 |

## 1. 为什么放弃「从录播抠人」

第一版的做法是从直播录屏里把人抠出来（`prepare_live.py` 的序列 + 圆窗/竖幅画框）。
它在「人物在画面里」这一层是成立的，但**做不了穿插**：

1. **边缘本来就不干净**。直播画面 16:9、码率经过一次压缩，发丝、袖口、羽毛的
   边缘在源头就已经是半透明的糊边。抠像只能猜，猜出来一圈毛边 ——
   文字从身后穿过时，那圈毛边读作「脏」。
2. **帧间不连续**。人一直在动，逐帧抠像的边界在帧与帧之间跳，成片里是「一张会
   抖动的人形贴纸」。
3. **没有可穿透结构**。穿插效果成立的物理前提是「她身上本来就有洞」：
   发缝、羽毛间隙、手臂与身体之间的空档。抠像把这些洞要么填死、要么打碎。

立绘（`C:\Users\Tsing\Pictures\管人立绘\岁己立绘`，146 张 PNG）恰好把这三条都解决了：
**alpha 是画师切好的**，边缘干净；**同一张图整镜不变**，不会抖；**发丝与羽翼的
间隙是真透明**，文字从身后画过去时会从缝隙里透出来。

## 2. 怎么选图（判据是可量的，不是审美口彩）

`figart.py` 对每张图量三个数：

| 指标 | 含义 | 为什么要它 |
|---|---|---|
| `cuts` | bbox **胸部高度带**（26%~78%）上，alpha 扫描线的平均「实体↔透明」交界数 | 文字是横排的。每一处交界都会把一句话切开一刀 —— 这就是「穿过去」在像素上的定义 |
| `mass` | 同一高度带上实体像素的平均占比 | 只有交界也不行：整张图碎成飘带时字全漏过去，读作「没挡住」。理想值 ≈ 0.55 |
| `op` | 整张画布「有任何不透明」的比例 | `> 0.96` 说明**没有真透明**（多半是 JPG 转的 PNG）。这种图压上去是一整块色块，穿插不可能成立 → 直接被 `lib()` 排除 |

综合分 `score = 0.55·min(1, cuts/8) + 0.45·(1 - |mass-0.55|/0.55)`，只用于排序。
分类 `kind` 看的是**人物包围盒**（alpha bbox）的长宽比，不是画布：
画布常常是 1170×2532 的整块透明纸，按画布分会把「胸像」和「全身」混成一类。

    python tools/pv_art.py doctor                     # 目录在不在、多少张能用
    python tools/pv_art.py list --kind bust --min-w 700 --top 20
    python tools/pv_art.py sheet --kind bust            # 出带编号的接触表，肉眼定稿
    python tools/pv_art.py pick --kind bust             # 自动挑分数最高的一张

**自动挑只给候选。** 分数能算出「有没有缝」，算不出「缝是不是正好落在歌词那一行」，
所以最终由人看图定稿；定稿后把文件名写进 `--fig-art`，渲染就是确定的、可复现的。

### 本片（《小丑的品格》2026-11-01）的定稿与理由

| 用途 | 文件 | 尺寸 | cuts | mass | 理由 |
|---|---|---|---|---|---|
| 主力 | `1211081868701597696_100@repost.png` | 760×1000 | 7.3 | 0.56 | 红帽 + 白羽袖半身像。**两侧展开的羽翼正好落在歌词高度**，羽毛间隙提供 4~12 处交界；实心占比 0.56 意味着「一半遮、一半透」，正是穿插需要的比例。红白配色也贴合「小丑 / 马戏」的主题 |

## 3. 特效怎么实现

### 3.1 数据：编排稿里多了 `fig.art`

```json
"fig": {
  "layer": "split", "splitAt": 0.62,
  "art": { "src": "C:/Users/.../1211081868701597696_100@repost.png",
           "w": 760, "h0": 1000, "h": 0.88, "a": 1.0, "shadow": 0.22, "at": 0.0,
           "fromSpan": true }
}
```

写进编排稿而不是只留在命令行，是因为**编排稿必须自包含**：换入口（`pv_stills`、
`render_song`、别人手里）渲染时不能因为「少传一个参数」就丢掉这一层。

`art` 与 `seq` 互斥：`pv_direct` 在挂立绘时会 `pop` 掉 `seq / tOff / wDur / win`，
否则 `_check_live_spans` 会拿 `tOff` 去核算「窗口起点」，报一堆假错。

### 3.2 绘制：`drawArt`

- **纯 alpha 合成**：没有窗、没有遮罩、没有羽化。立绘的边缘就是画师给的边缘，
  再揉一遍只会糊成一团光。`shadow` 只在她身后压一道偏移柔影（0.22 左右），
  让她「站在纸里」而不是浮着 —— 描边会读作贴纸。
- **动势**：`bob`（呼吸漂移）+ `zoom`（镜内缓推）+ `fadeIn/out` + `at`（镜内延后出现）。
  全部是 `t` 的纯函数 ⇒ 同一 `t` 双渲字节一致，确定性验收不受影响。
- **镜头耦合**：`camGain`（0=屏幕空间固定 / 1=跟随镜头 / 中间=视差）与 live 同款，
  由 `drawFigureWithCam` 统一套 `applyCam`。
- **分层后期**：`--grade-fig` 的 CSS filter 同样作用在立绘上（`shot.grade.fig`）。

### 3.3 穿插：两趟绘制夹一次人物

引擎里原本就有场景 C 的通道（`lyric_split`）：

```
drawLyrics(ctx, shot, t, 'behind')     ← 后段字先画
drawFigureWithCam(...)                 ← 立绘（真 alpha）盖在它上面
drawLyrics(ctx, shot, t, 'front')      ← 前段字压在她身上
```

`pickTier` 按阅读序把同一句的字形切成两段（`fig.splitAt`，前段在人物**前**）。
立绘是**整块不透明 + 真实镂空**，所以后段字不会「整体消失」，而是从发缝、
羽翼间隙里透出来 —— 这才是「同一行字一半在人前、一半在人后」。

### 3.4 几何：她的左缘 = 字形块的 62%

这一步错了，前面全白做（而且画面看起来「没错」，只是永远没有交错）：

```
左缘 = 字形 bbox 的 x0 + (x1-x0) × 0.62
splitAt = 0.62            ← 与上式成对出现
```

- 用**字形** bbox 而不是版面 bbox：版面 bbox 把规则线、索引、注记也算进去，
  右侧常比最后一个字多出几百像素。用版面 bbox 定位时实测「她的左缘落在最后
  一个字外面」—— 字根本没穿过去，只有一个字的边角被啃掉。
- 62% 是折中：更小（如 0.44）她会压在一整行字中间、把脸挡在字底下；更大（0.75）
  她基本站在字外面，看不出交错。
- 立绘宽度由**源图真实长宽比**反推（`w = h × iw/ih`），写死比例的话换一张图就横向
  拉伸 —— 和「从录播抠人」是同一种失败。

> 踩坑记录：`tools/pv_spans.py` 生成的挂点表里带了 `x: 0.44`（那是圆窗/竖幅贴边
> 那套几何的遗留字段）。它会让引擎永远按 0.44 摆，**按 bbox 自动定位的那段等于没写**。
> 现象是「切点改 0.5 / 0.62 / 0.75 渲染出的 PNG 字节完全相同」。挂立绘时必须清掉。

## 4. 用法

```bash
# 只给「已经标了 split 的镜头」挂立绘（默认）
python tools/pv_one.py --date 2026-11-01 --song 小丑的品格 --artist 泠鸢yousa \
       --from-segments --live-json _tmp/mvg/live2/live.json \
       --fig-spans _tmp/mvg/spans3.json --fig-art "#5"

# 全部有人的镜头都换成同一张立绘
python tools/pv_one.py ... --fig-art 1211081868701597696_100@repost.png --fig-art-shots all

# 调参
--fig-art-h 0.88        # 画布高度占比
--fig-art-x 0.62        # 横向中心占比（缺省按字形 bbox 自动）
--fig-art-shadow 0.22   # 座影不透明度
--fig-art-at 1.5        # 镜内 1.5s 后才出现
--fig-art-split 0.62    # 顺带把选中镜头标成分层并指定切点

# 单独验证一帧（不编码）
node tools/pv_stills.cjs --sb _tmp/mvg/art_out/storyboard.json \
     --live _tmp/mvg/live2/live.json --times 13,71.5 --out _tmp/mvg/finB
```

素材目录可用环境变量覆盖（换一套立绘不必改代码）：

```bash
set SUI_ART_DIR=D:\我的立绘
```

## 5. 验收口径

| 项 | 判据 | 本片实测 |
|---|---|---|
| 素材带真透明 | `op < 0.96`，否则 `art.opaque` 报 error | 146 张里 145 张通过 |
| 文件存在 | `art.src_missing` | 0 |
| 可切分 | `cuts ≥ 4` 且 `mass ∈ [0.4, 0.75]` | #5：7.3 / 0.56 |
| 真的交错 | 同一句里既有字压在她身上、又有字被她挡住（肉眼看抽帧） | 13s / 71.5s / 92s 三帧均成立 |
| 确定性 | 同一 job 再渲一次，视频流 MD5 一致 | 抽帧双渲字节一致 ✅ |
| 无回归 | 不传 `--fig-art` 时编排稿逐字段与旧版相同 | 旧 job 重渲 MD5 不变 |

## 6. 已知边界

- **单张静态图**：没有口型、没有手势。要「跟着唱」仍是 `footage`（录播序列）的活。
  两条路可以同时存在：普通镜头用录播，需要穿插的句子用立绘。
- **只对横排字成立**：竖排歌词（`vRuler`）旁边的「穿缝」读不出来，因为扫描线是横的。
- **`cuts` 是扫描线指标**：它不知道「缝在什么高度」。所以自动挑完必须抽帧看一眼。
